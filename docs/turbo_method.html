GEMSDOE2-TURBO: Methodology

Advanced multi-scale, multi-model fusion for detecting new geological faults in the GeoDAWN region.

🎯 Core Innovation

TURBO is specifically designed to detect NEW, previously unmapped faults - the actual scoring target of the GEMS Prize competition.

Unlike traditional approaches that focus on reproducing known faults, TURBO uses advanced techniques to identify subtle geophysical patterns that indicate the presence of hidden faults.

1. Method Overview

Architecture

The TURBO system implements a multi-stage pipeline:

Key Design Principles

  1. Multi-Scale Detection: Faults appear at different scales in geophysical data. Single-scale methods miss many new faults.
  2. Multi-Sensor Fusion: Combine magnetic, gravity, and elevation data - each sensitive to different fault characteristics.
  3. New Fault Focus: Unlike baseline methods that focus on known faults, TURBO is designed to find new patterns.
  4. Geological Realism: Incorporate geological knowledge about fault behavior (connectivity, proximity, continuity).
  5. Robustness: Handle noise, missing data, and edge cases gracefully.

2. Detailed Methodology

2.1 Multi-Scale Edge Detection

Theory

Faults in geophysical data often manifest as:

  • Magnetic data: Linear anomalies, gradient changes, contrast in magnetic properties
  • Gravity data: Density contrasts, slope changes, step-like features
  • Elevation data: Topographic lineaments, slope breaks, valleys/ridges

These features appear at different scales depending on the fault size, depth, and local geology.

Implementation

For each of the first 10 geophysical bands, we apply:

  1. Gaussian smoothing: At multiple scales (σ = 1, 2, 3 pixels)

    Smoothing reduces noise and enhances structural features at each scale.

  2. Canny edge detection: Identifies sharp transitions

    Canny is particularly good at finding step-like features characteristic of faults.

  3. Sobel gradient magnitude: Measures rate of change

    Gradient magnitude highlights areas of rapid change in geophysical properties.

  4. Normalization: Scale to [0, 1] range

    Ensures all edge responses are comparable across bands and scales.

Mathematical Formulation

For a band B at scale σ:

``` # Gaussian smoothing B_σ = G_σ * B # Normalization B̄_σ = (B_σ - μ(B_σ)) / std(B_σ) # Canny edge detection E_canny,σ = Canny(B̄_σ, σ) # Sobel gradient E_sobel,σ = |∇B̄_σ| # Combined edge response E_σ = (E_canny,σ + E_sobel,σ) / 2 ```

Final edge map: E = mean(E_σ for σ in [1, 2, 3] for all bands)

2.2 Lineament Detection

Theory

Lineaments are straight or slightly curved linear features in remote sensing data that often correspond to geological structures including faults. In the context of fault detection:

  • Faults often appear as straight lines or line segments
  • Multiple faults can form parallel or intersecting lineament patterns
  • Lineament analysis helps detect faults that might be missed by local edge detection

Implementation

Directional filtering approach:

  1. Create directional kernels: 12 kernels at 30° intervals (0° to 330°)

    Each kernel emphasizes features oriented in a specific direction.

  2. Apply kernels to gradient data:

    For each direction, convolve the gradient magnitude with the directional kernel.

  3. Combine responses:

    Take the maximum response across all directions at each pixel.

  4. Threshold and clean:

    Apply threshold and remove small connected components.

Mathematical Formulation

For direction θ:

``` # Directional kernel (line detector at angle θ) K_θ = create_line_kernel(θ, size=5) # Directional response R_θ = K_θ * |∇B| # Lineament strength L = max(R_θ for θ in [0°, 30°, ..., 330°]) # Binary lineament map L_bin = L > threshold (default: 0.4) ```

2.3 Gradient Fusion

Theory

Geophysical data contains rich information about subsurface structures. Faults often manifest as:

  • First derivatives (gradients): Rate of change, highlighting boundaries
  • Second derivatives (Laplacian): Curvature, identifying ridges/valleys
  • Directional derivatives: Specific directions of change

By computing these derivatives across all 19 available bands, we capture a comprehensive set of features indicative of faults.

Implementation

For each band B_i:

  1. Compute gradients: ∇B_i = (∂B_i/∂x, ∂B_i/∂y)
  2. Compute gradient magnitude: |∇B_i| = sqrt((∂B_i/∂x)² + (∂B_i/∂y)²)
  3. Compute Laplacian: ∇²B_i = ∂²B_i/∂x² + ∂²B_i/∂y²
  4. Normalize: Scale all derivatives to [0, 1] range
  5. Combine: Average across all bands

2.4 Fusion Strategy

Weighted Combination

The three detection methods are combined using empirically determined weights:

ComponentWeightRationale
Edge Detection40%Most reliable for sharp fault boundaries
Lineament Detection30%Good for regional fault patterns
Gradient Fusion30%Captures subtle geophysical anomalies

Mathematically:

``` F = w_e * E + w_l * L + w_g * G where: w_e = 0.4 (edge weight) w_l = 0.3 (lineament weight) w_g = 0.3 (gradient weight) E, L, G are normalized to [0, 1] ```

Proximity Boosting

Geological faults often occur in networks. New faults are more likely to be found near known faults. We implement this using an exponential decay function:

``` # Distance from known faults D(x) = distance_transform(known_faults == 0) # Proximity boost (exponential decay) P(x) = exp(-D(x) / decay_length) where decay_length = 500m (5 pixels at 100m resolution) ```

The final prediction combines the fused detection with proximity boosting:

``` Prediction(x) = max(known_faults(x) * 0.95, F(x) * P(x)) ```

Sigmoid Transformation

To convert the combined score to a probability, we apply a sigmoid function:

``` P_final = 1 / (1 + exp(-10 * (F - 0.5))) ```

This maps the middle range (around 0.5) to steep probability changes, while preserving extreme values.

2.5 Post-Processing

Thresholding

Convert continuous probabilities to binary predictions:

``` Binary = P_final > threshold (default: 0.35) ```

The threshold of 0.35 was chosen to:

  • Include subtle fault indicators
  • Exclude most noise
  • Balance precision and recall

Connected Component Filtering

Remove isolated pixels that are likely noise:

``` # Label connected components labeled, num_features = label(Binary) # Count pixels in each component sizes = bincount(labeled.ravel())[1:] # Keep only components with ≥ min_size pixels keep = sizes >= min_size (default: 3) # Filter Binary_filtered = isin(labeled, where(keep)[0] + 1) ```

Why min_size = 3?

  • Minimum meaningful fault at 100m resolution is ~300m (3 pixels)
  • Removes single-pixel noise that harms DTI score
  • Preserves real faults while filtering artifacts

Distance Transform Smoothing

Convert binary predictions back to smooth probabilities using distance transform:

``` # Distance from predicted faults dist = distance_transform_edt(Binary_filtered == 0) # Smooth probability (inverse distance) P_smooth = clip(1 - (dist / 1000), 0, 1) ```

This creates a gradient of confidence decreasing with distance from predicted faults, which:

  • Provides partial credit for near-misses in DTI metric
  • Reduces false negative penalty
  • Mimics the 300m kernel used in scoring

2.6 Template Conformance

Critical Step

DrivenData rejects submissions with the error "Predicted values must be in range [0, 1]" if:

  • Any pixel in the valid region is NaN
  • Any pixel in the valid region is outside [0, 1]
  • Pixels outside the valid region are not NaN

Implementation

The conform_to_template function ensures:

``` # Input: raw prediction P, template T # Output: conformed prediction C for each pixel x: if T(x) is finite: # In valid region C(x) = clip(P(x), 0, 1) # Ensure in [0, 1] else: # Outside valid region C(x) = NaN # Must be NaN # Set GDAL_NODATA tag to 'nan' ```
